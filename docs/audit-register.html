01

Critical security

6 findings
SEC-01

Leaderboard scores are client-authored, unvalidated and unbounded

  • supabase/schema.sql:52–73
  • lib/cloud/results.ts:63–88
  • lib/cloud/buildResult.ts:96–110

results accepts a direct client insert under with check (auth.uid() = user_id). That is the only check — score, verdict and metrics are whatever the browser sends.

  • Forgeable rankings. Any signed-in player can post score: 999999999 with any verdict string. The global board, the /r/{id} statement and the OG card all render it as fact.
  • No size caps. verdict is bare text, metrics bare jsonb. One insert can carry megabytes into a public-read table, with no per-user rate limit.
  • No enum on verdict, though the app only ever produces the six values in lib/verdict.ts.
Recommended fix 
-- Move scoring behind a SECURITY DEFINER RPC that recomputes from a run
-- transcript. At minimum, revoke direct insert and constrain the shape:
revoke insert on public.results from authenticated;

alter table public.results
  add constraint results_score_range   check (score between -1e12 and 1e12),
  add constraint results_verdict_len   check (char_length(verdict) <= 64),
  add constraint results_metrics_size  check (pg_column_size(metrics) <= 8192);

-- and cap submissions per player per hour
create unique index results_hourly_cap
  on public.results (user_id, mode, date_trunc('hour', created_at));
SEC-02

Every player's friend code is world-readable

  • supabase/schema.sql:44–45
  • lib/cloud/generate.ts:36–39

The policy comment says leaderboards show “username + avatar only”. The policy itself grants every column: 

create policy "profiles - public read" on public.profiles
  for select using (true);

That includes friend_code — the single secret gating a friend request. Any client can select friend_code from profiles and enumerate the userbase. The code is also generated with Math.random() over 31⁶ ≈ 887M, so it was never built to withstand guessing; it was built to stay private.

Recommended fix 
drop policy "profiles - public read" on public.profiles;

create policy "profiles - own row" on public.profiles
  for select using (auth.uid() = id);

create view public.profiles_public as
  select id, username, avatar_seed from public.profiles;
grant select on public.profiles_public to anon, authenticated;

create function public.profile_by_friend_code(code text)
returns table (id uuid, username text, avatar_seed text)
language sql security definer set search_path = public as $$
  select id, username, avatar_seed from profiles where friend_code = upper(code);
$$;

Then point getProfiles and getByFriendCode at the view and the RPC.

SEC-03

Friendship isn't mutual — anyone can befriend you unilaterally

  • lib/cloud/friends.ts:70–84, 100–110
  • supabase/schema.sql:105–112

The file header claims “RLS lets each user write only their own side, so friendship is mutual-accepted.” It isn't. accept() writes an accepted edge on the caller's own side, and listFriendIds() counts an accepted edge in either direction: 

// accept() — no check that anything was ever offered
await supabase.from("friends").upsert(
  { user_id: userId, friend_id: friendId, status: "accepted" },
  { onConflict: "user_id,friend_id" },
);

// listFriendIds() — one edge, counted from both ends
if (e.status !== "accepted") continue;
ids.add(e.userId === userId ? e.friendId : e.userId);

So A inserts (A → B, accepted) with no involvement from B, and B's client then lists A as a friend. Combined with SEC-02, any user can insert themselves into any other user's friends leaderboard.

Recommended fix 
create policy "friends - accept only what was offered" on public.friends
  for insert with check (
    auth.uid() = user_id and (
      status = 'pending'
      or exists (select 1 from friends f
                 where f.user_id = friends.friend_id
                   and f.friend_id = auth.uid())
    )
  );
// lib/cloud/friends.ts — both sides must have said yes
const mine   = new Set(edges.filter(e => e.userId === userId   && e.status === "accepted").map(e => e.friendId));
const theirs = new Set(edges.filter(e => e.friendId === userId && e.status === "accepted").map(e => e.userId));
return [...mine].filter(id => theirs.has(id));
SEC-04

PostgREST filter built by string interpolation

  • lib/cloud/friends.ts:89–96
.or(`user_id.eq.${userId},friend_id.eq.${userId}`)

userId lands straight inside PostgREST filter syntax. Today it is a UUID from auth and RLS bounds the blast radius to the caller's own rows, so this is not currently exploitable — but it is an injection primitive one refactor away from mattering, the day a friend id arrives from a URL or a room payload. Every other query in the codebase uses parameterised builders; this is the exception.

Recommended fix 
const [asOwner, asTarget] = await Promise.all([
  supabase.from("friends").select("*").eq("user_id", userId),
  supabase.from("friends").select("*").eq("friend_id", userId),
]);
return [...(asOwner.data ?? []), ...(asTarget.data ?? [])].map(fromRow);

SEC-06

The CSP protects against framing only; no HSTS

  • next.config.ts:7–13
{ key: "Content-Security-Policy",
  value: "frame-ancestors 'none'; object-src 'none'; base-uri 'self'" }

The header comment is honest that this is “the pragmatic set” with no script-src. The result contributes nothing against injected script. Given that the app renders user-authored strings — usernames from profiles, verdicts from results, peer names off the multiplayer wire — a real script-src and connect-src would be meaningful defence in depth. Strict-Transport-Security is absent too (Vercel supplies it; a self-hosted deploy would not).

Recommended fix 
const SUPA = process.env.NEXT_PUBLIC_SUPABASE_URL ?? "";
{ key: "Content-Security-Policy", value: [
    "default-src 'self'",
    // Next's inline bootstrap needs 'unsafe-inline'; move to a nonce with middleware
    "script-src 'self' 'unsafe-inline'",
    "style-src 'self' 'unsafe-inline'",
    "img-src 'self' data: blob:",
    "media-src 'self'",
    "font-src 'self' data:",
    `connect-src 'self' ${SUPA} wss://${SUPA.replace(/^https?:\/\//, "")}`,
    "frame-ancestors 'none'", "object-src 'none'", "base-uri 'self'",
  ].join("; ") },
{ key: "Strict-Transport-Security",
  value: "max-age=63072000; includeSubDomains; preload" },

BUG-01

Cloud guests break useProfile — 11 dead requests and an empty Money Brain

  • hooks/useProfile.ts:26–63
  • lib/cloud/profiles.ts:43–77
  • lib/cloud/identity.ts:60–64

useProfile resolves identity with resolveProgressId, which deliberately returns a device-… id for guests even in cloud mode. It then hands that id to ensureProfile, which — unlike its siblings cloudSavesFor and cloudMasteryFor — has no guest guard: 

export async function ensureProfile(userId: string): Promise<Profile> {
  const existing = await getProfile(userId);  // uuid column vs "device-…" → error → null
  if (existing) return existing;
  if (isCloud && supabase) {                  // ← no !isGuestId(userId)
    for (let attempt = 0; attempt < MAX_CREATE_ATTEMPTS; attempt++) { … }
    throw new Error("Could not create profile after multiple attempts");

Every mount fires ~11 doomed requests, then throws. Because load() uses Promise.all, the throw discards the streak and mastery results too, and the effect has a finally but no catch — an unhandled rejection each time. The user-visible symptom is the exact one the codebase fights elsewhere: a report announcing “this run sharpened Compounding, Windfalls…” above a Money Brain reading 0%.

Recommended fix 
// lib/cloud/profiles.ts — the guard its siblings already have
function cloudProfileFor(userId: string): boolean {
  return Boolean(isCloud && supabase && !isGuestId(userId));
}
// then swap every `isCloud && supabase` in getProfile / ensureProfile /
// updateUsername for cloudProfileFor(userId) — and add a catch in useProfile
// so one failed store never blanks the other two.
BUG-02

The Rat Race stock book creates money through rounding

  • lib/cashflow/engine.ts:226 vs :255

Buys settle in cents; sells settle in whole dollars.

// buyStock — cents
const cost = Math.round(n * price * 100) / 100;

// sellStock — dollars
return { ...s, cash: s.cash + Math.round(n * price), stocks };

A buy-then-sell at an unchanged quote is therefore not value-neutral: one share of a $2.95 ticker costs $2.95 and returns $3.00. The swing is bounded at ±$0.50 per transaction but it is repeatable, and it leaves fractional residue in cash that flows into clampCash and netWorth. maxAffordable already went to the trouble of working in integer cents precisely to avoid this class of drift.

Recommended fix 
// sellStock — settle both sides identically
const proceeds = Math.round(n * price * 100) / 100;
return { ...s, cash: s.cash + proceeds, stocks };
BUG-03

loadCashflow feeds unvalidated localStorage into the engine

  • lib/cashflow/persist.ts:44–56
const s = JSON.parse(raw) as CashflowState;
if (!s || typeof s.version !== "number") return null;
if (s.version === STATE_VERSION) return s;   // ← every other field unchecked

Only version is inspected. A truncated write or a hand-edited key resumes as a corrupt state: totalExpenses and payday sum their fields with +, so a single undefined becomes NaN and propagates through the whole statement, the Freedom meter and the submitted leaderboard score. Compare the multiplayer path, which rebuilds every field in parseRunState.

Recommended fix 
function isCashflowState(s: unknown): s is CashflowState {
  if (typeof s !== "object" || s === null) return false;
  const c = s as Partial<CashflowState>;
  return c.version === STATE_VERSION
    && !!c.liabilities && !!c.expenses
    && Array.isArray(c.stocks) && Array.isArray(c.realEstate) && Array.isArray(c.businesses)
    && Number.isFinite(c.cash) && Number.isFinite(c.salary) && Number.isFinite(c.seed);
}
// loadCashflow: if (s.version === STATE_VERSION) return isCashflowState(s) ? s : null;
BUG-04

advanceYear records a debt payment the player never made

  • lib/runEngine.ts:598–640

The lender's minimum comes from cash first, then a forced sale — and both may fall short:

const due = debtMinimum(debt);
…
debt -= fromCash + forcedSale;   // only what was actually paid

// …but the year's statement line claims the whole amount left:
cashFlow: Math.round(takeHome - expenses - ms.payment - due),

For a player with no cash and no holdings — precisely the insolvency spiral the engine goes to great length to model — the printed cash flow overstates the outflow by due − (fromCash + forcedSale), so the receipt stops reconciling against the balance change. The comment on that line (“the figure the player sees is the one they lived”) is the intent; the code doesn't meet it.

Recommended fix 
const paid = fromCash + forcedSale;   // hoist out of the `if (due > 0)` block
…
cashFlow: Math.round(takeHome - expenses - ms.payment - paid),
BUG-05

startMatch can build a nine-seat roster every peer then truncates

  • hooks/useMatch.tsx:1349–1356
  • lib/mp/protocol.ts:221
const roster = Object.values(peersRef.current).filter(p => p.connected)
  .sort(…).slice(0, MAX_PLAYERS)            // up to 8
  .map(…);
if (!roster.some(r => r.playerId === cur.hostId) && selfInfoRef.current) {
  roster.unshift(selfInfoRef.current);      // → 9
}

parseMatchConfig truncates every inbound roster to MAX_PLAYERS, dropping the last entry. The host would then believe a player is seated whom the rest of the room refuses — and since the roster is also the rejoin gate, that player is permanently locked out with “the host started the match without you”. Presence caps others at 7, so this is hard to reach today, but the invariant is one line.

Recommended fix 
if (roster.length > MAX_PLAYERS) roster.length = MAX_PLAYERS;
BUG-06

pickIndex returns index 0 for an empty deck

  • lib/cashflow/rng.ts:29–31
  • lib/cashflow/engine.ts:204–207
return Math.floor(rngAt(seed, cursor) * len) % Math.max(1, len);

With len === 0 this returns 0, and draw() then hands back deck[0] === undefined as a card. Every caller destructures .card and reads fields off it. The Math.max(1, len) guard protects the modulo but not the caller.

Recommended fix 
export function pickIndex(seed: number, cursor: number, len: number): number {
  if (len <= 0) return -1;
  return Math.floor(rngAt(seed, cursor) * len) % len;
}
BUG-07

saveMatch deletes other rooms on any storage failure

  • lib/mp/matchStore.ts:125–133
for (;;) {
  try { store.setItem(keyFor(roomCode), body); evict(store, roomCode); return; }
  catch { if (!dropOldest(store, roomCode)) return; }
}

The loop assumes every setItem throw is a quota error. It isn't — Safari private mode and “block all cookies” throw unconditionally. In that case the loop deletes every other stored match record before giving up, destroying rejoin data for rooms that had nothing to do with this write. The comment explains why swallowing the error is wrong; the retry over-corrects.

Recommended fix 
catch (e) {
  const quota = e instanceof DOMException &&
    (e.name === "QuotaExceededError" || e.name === "NS_ERROR_DOM_QUOTA_REACHED");
  if (!quota || !dropOldest(store, roomCode)) return;
}
03

Quality & performance

7 findings
QUA-01

The leaderboard over-fetches and dedupes on the client

  • lib/cloud/results.ts:90–116
const { data } = await query.limit(limit * 5);   // 125 rows over the wire
return bestPerUser((data ?? []).map(fromRow)).slice(0, limit);

Two problems. The transfer grows linearly with board size, and correctness is only probabilistic: if one prolific player owns the top 125 rows, the board renders one entry. Push the dedupe into Postgres.

Recommended fix 
create view public.results_best as
  select distinct on (user_id, mode) * from public.results
  order by user_id, mode, score desc, created_at desc;
QUA-02

ShareCard holds a multi-megabyte data URL in React state

  • components/share/ShareCard.tsx:47

setPreview(cv.toDataURL("image/png")) base64-encodes a 1080×1920 PNG (≈1.33× the raw bytes) into a string that lives in state, is diffed by React, and is re-parsed as an <img src>. URL.createObjectURL(blob) avoids the encode, the copy and the diff — and the component already has a toBlob() helper. Revoke on unmount and on format change.

QUA-03

Identity generators are undersized and non-cryptographic

  • lib/cloud/generate.ts:29–39
  • lib/mp/roomCodes.ts:9–22

generateUsername() draws from 24 × 24 × 900 ≈ 518k combinations against a UNIQUE constraint with only five retries — collision pressure rises quadratically with the userbase, and exhausting the retries throws (swallowed by submitRunOnce, so the run silently never posts). generateFriendCode() uses Math.random(), which is not a CSPRNG. lib/mp/roomCodes.ts already does this correctly with crypto.getRandomValues and rejection sampling — reuse that helper, and append a random suffix to usernames.

QUA-04

Match messages carry no sender authentication — accepted risk

  • hooks/useMatch.tsx:746–863

snapshot, snapshotReply and config are trusted on the strength of the playerId inside the payload; the transport binds no sender identity. The code is candid about this — “airtight needs a server authority, which is out of scope by contract” — and mitigates it well with roster gating, session fencing, and a tick bounded by demonstrable peer years. Worth recording as an accepted risk rather than a defect: a room member who knows the code can still rewrite an absent player's cached life. Binding sends to the Realtime presence key would close it.

QUA-05

drawEvents spins its full guard when the eligible pool is thin

  • lib/runEngine.ts:211

The solo branch loops to its 60-iteration guard whenever the eligible pool holds fewer distinct events than want. Break when picks.length === new Set(weighted).size.

QUA-06

The OG route's upstream fetch has no timeout

  • app/api/og/[id]/route.tsx:41

The Supabase read has no AbortSignal.timeout(). On an edge function a slow upstream holds the request until the platform kills it — and the generic fallback card exists precisely so this never blocks. Add { signal: AbortSignal.timeout(1500) }; the existing catch already returns the fallback.

QUA-07

The one standing lint warning

  • components/share/ShareCard.tsx:132

@next/next/no-img-element on a raw <img>. It's legitimate here — the source is a data or blob URL that next/image can't optimise — so silence it with an inline eslint-disable-next-line and a one-line note, rather than leaving a warning standing in an otherwise clean run.
